## 一句话总结

DCT+BPE 把动作块压成少量 token，让自回归 VLA 学会 50Hz 灵巧任务，追平 π0 且训练快 5 倍。

## 背景与动机

- **之前的方法有什么问题？**
  - 自回归 VLA（RT-2、OpenVLA 等）要先把连续动作变成离散 **token**（模型能读写的离散符号）。此前通用做法是**朴素 binning**：每个时间步、每个维度各自切成 256 个区间。
  - 原文发现这种方案"在从高频机器人数据学习灵巧技能时通常表现很差"。原因在学习目标本身：自回归模型的学习信号正比于"下一个 token 相对前文的**边际信息量**"。动作是平滑信号，控制频率越高、每步变化越小，这个信息量趋近于零，模型最容易学到的就是"复制上一个 token"。
  - 论文第 IV 节的玩具实验证实了这一点：让小 Transformer 根据 4 个随机点预测一条三次样条，把采样率从每段 25 点提到 800 点，binning 方案的预测误差陡增，最后模型只会复制第一个动作。现实中的对应现象：OpenVLA 在低频的 BridgeV2、RT-1 上有效，却难以拟合 15 Hz 的 DROID。
  - 另一个代价是 token 太多：1 秒 50 Hz 的 14 维双臂动作要 700 个 token，训练难、推理慢。
- **为什么这个问题重要？**
  - 自回归路线不需要改骨干结构，能直接复用任何预训练 Transformer 和成熟的 LLM 训练工具链；扩散 / 流匹配（如 π0）效果好但训练成本高。如果能修好 token 化，就能同时获得"训练简单快速"和"灵巧高频"。
  - 类比：把一首歌逐个采样点念出来，念到后面每个数都跟前一个几乎一样，听的人学不到旋律；换成 MP3 的频率编码，几个系数就能描述整段旋律。

> 💡 要点：论文的核心洞见是"动作信号在训练前必须先**压缩**，以降低相邻 token 的相关性"。FAST 本质上是把 JPEG / MP3 那套频域压缩思想搬到了机器人动作上。

## 方法

### 整体框架

```mermaid
flowchart LR
  A["动作块 a_1..a_H<br/>(1 秒, H×D 矩阵)"] --> N["① 分位数归一化<br/>1%/99% → [-1, 1]"]
  N --> D["② 每维 DCT<br/>时域 → 频域"]
  D --> Q["③ × 缩放系数 γ 后取整<br/>稀疏系数矩阵"]
  Q --> F["④ 低频优先展平<br/>成整数序列"]
  F --> B["⑤ BPE 编码<br/>词表 1024"]
  B --> T["30~60 个动作 token"]
  T --> V["自回归 VLA<br/>(π0 骨干 PaliGemma-3B)"]
  V -->|预测 token| I["逐步可逆解码"] --> R["连续动作块"]
```

### 关键模块

#### 模块 1：基于 DCT 的时间序列压缩

- **输入**：归一化后的动作块，每个维度是一条长度 H 的时间序列。
- **处理**：对每个动作维度单独做 **DCT**（离散余弦变换：把信号表示成不同频率余弦波的加权和）。低频系数描述整体走势，高频系数描述突变；平滑的机器人动作绝大部分信息集中在少数低频系数里。
- **输出**：每维 H 个频率系数。
- **为什么这样设计**：DCT 是解析变换，不需要训练，速度快；相比学习式的向量量化（VQ）编码器，没有繁琐的训练和逐数据集调参。原文指出任何足够有效的压缩方法都能提升 VLA 训练速度，DCT 是在简单性与效率之间的务实选择。

#### 模块 2：FAST token 化算法

- **输入**：原始动作块。
- **处理**（算法 1）：
  1. 归一化：每个维度按训练集的第 1 和第 99 百分位数映射到 [-1, 1]，对离群动作鲁棒，也让不同机器人的动作量纲统一。
  2. 逐维 DCT。
  3. "缩放后取整"：系数乘缩放系数 γ 再四舍五入，小系数归零，矩阵变稀疏；γ 是在有损程度与压缩率之间权衡的超参数。
  4. 展平：按"列优先"顺序，即先排所有维度的最低频系数、再排次低频，原文说这样让自回归模型先预测决定整体形状的低频部分，rollout 更稳定。
  5. **BPE**（字节对编码：反复把最常同时出现的符号对合并成新符号）无损压缩这串整数，把大量 0 "压扁"，并合并跨维度的常见系数组合。
- **输出**：变长的动作 token 序列。
- **为什么这样设计**：全部操作可逆，解码快；只有两个超参数（缩放系数、BPE 词表大小），原文说它们"不太敏感"，所有单数据集实验统一用缩放 10、词表 1024。选 BPE 是因为实现成熟、输出固定大小词表，可直接并入 VLM 的词表。

#### 模块 3：FAST+ 通用 tokenizer

- **输入**：约 100 万个 1 秒动作块，来自单臂、双臂、移动机器人，含关节空间与末端空间（世界系、相机系）多种参数化，频率 5~50 Hz；所有动作补零到 32 维（混合比例见原文附录 A）。
- **处理**：用上述流程训练一个 BPE 词表。
- **输出**：可当黑盒使用的 tokenizer，HuggingFace `AutoProcessor` 三行调用，也可用 `fit` 在新数据上重训。
- **为什么这样设计**：BPE 是流程里唯一需要训练的部件，虽然只要几分钟，但给使用增加了摩擦；通用版省掉这一步。原文建议输入先做分位数归一化，并按 1 秒切块。

#### 模块 4：π0-FAST 策略训练

- **输入**：2~3 张 224×224 图像（一个第三人称相机 + 每条臂一个腕部相机）、语言指令、本体状态（本体状态用 256 bin 离散后当文本 token 输入，因为输入端不存在冗余 token 的学习问题）。
- **处理**：骨干用 π0 的 PaliGemma-3B（也测试了 OpenVLA 的 Prismatic-7B）；把 1 秒动作块 FAST token 化后，覆盖 VLM 词表中最少使用的 token，全参数微调。训练超参：线性预热 1k 步后恒定学习率 5e-5，AdamW 无权重衰减，梯度裁剪 1，权重 EMA 0.999。推理用贪心解码，双臂任务加一个小温度以免策略停在初始位置。
- **输出**：自回归生成的动作 token，逐步逆变换成连续动作块。
- **为什么这样设计**：不改任何骨干结构，任何预训练自回归 Transformer 都能直接用。

> 🔗 关联：分位数归一化与 256 bin 离散化的基础见 [07 动作表示](../../VLA/Basic/07-action-representation.md) 7.3、7.4 节；本文是在那套"范式 A"上换掉了 token 化这一环。

## 实验

### 数据集 / 任务 / 基线

| 实验 | 平台 / 数据 | 频率 | 说明 |
|---|---|---|---|
| LIBERO | 仿真，Spatial / Object / Goal / Long 四套合并 27 万样本，一起训 40k 步 | — | 二值成功率 |
| 收拾桌子（Table Bussing） | UR5e 单臂，训练集约 70 种物体 | 20 Hz | 评测场景 12 个物体，按正确投放比例计分 |
| 叠 T 恤 | 双臂 ARX，约 150 件衬衫 | 50 Hz | 5 件已见衬衫，按折好比例计分 |
| 装杂货袋 | UR5e 单臂，7 件物品 | 20 Hz | 只用于通用策略的开箱评测 |
| 取吐司 | 双臂 Trossen ViperX（ALOHA 式） | 50 Hz | 4 分制进度，只用于通用策略 |
| 从篮子叠衣服 | 双臂 ARX，5 件衣物随机放入篮子 | 50 Hz | 最难任务，预训练 + 少量高质量数据微调 |
| DROID 零样本 | 7.5 万条成功轨迹（2100 万样本），3 个 epoch = 240k 步 @ batch 256，8×H100 约 4 天 | 15 Hz | 16 个任务共 44 次试验，全新场景、视角、物体 |

基线 / 对比对象：

- **朴素 binning**（RT-2、RT-2-X、OpenVLA 的方案），逐时间步离散再拼接。
- **FSQ**：学习式的量化压缩（VQ-VAE 的简化版），作为"同样压缩但需要训练网络"的消融。
- **FAST**（按数据集训练）与 **FAST+**（通用）。
- **π0 扩散/流匹配版**：最先进的连续动作 VLA。

### 主要结果

**1）压缩率（表 I，1 秒动作块平均 token 数）**

| 数据集 | 动作维度 | 频率 | 朴素 | FAST | 压缩比 |
|---|---|---|---|---|---|
| BridgeV2 | 7 | 5 Hz | 35 | 20 | 1.75 |
| DROID | 7 | 15 Hz | 105 | 29 | 3.6 |
| 收拾桌子 | 7 | 20 Hz | 140 | 28 | 5.0 |
| 叠 T 恤 | 14 | 50 Hz | 700 | 53 | 13.2 |

原文观察：FAST 在各领域都大致是"每条机械臂每秒约 30 个 token"，与采样频率基本无关。FAST+ 在训练时未见过的数据集（灵巧手、UMI、人形等，附录表 III）上也能把 token 数减少至少 2 倍。

**2）tokenizer 对比（图 6）**

- 朴素 binning 在 20 Hz 收拾桌子和 50 Hz 叠 T 恤上"无法推进任务"。
- 压缩式 token 化（FAST、FSQ）训练效率显著更高；FAST 与 FSQ 相当或更好，尤其在灵巧高频任务上。
- FAST+ 与按数据集定制的 FAST 表现接近。

**3）DROID 零样本泛化**

首次在完整 DROID 数据集上训出无需微调、仅靠自然语言提示即可在未见环境工作的策略；在 UC Berkeley、Stanford、University of Washington 三个校园做定性测试，能完成取放、开关柜门、打开水龙头等任务，失败时也表现出合理行为（如去够微波炉把手）。

**4）与扩散 π0 的对比（图 9、图 11）**

| 设置 | 结果 |
|---|---|
| 小数据集（LIBERO、叠 T 恤，50 小时） | 两者相当 |
| 大数据集（收拾桌子） | FAST 版收敛更快，达到高性能所需训练步数少 3 倍 |
| DROID 语言跟随 | 扩散版常忽略指令，FAST 版更贴合 |
| 通用策略（π0 完整混合数据：9.03 亿时间步自有数据 + 9.1% 开源数据） | π0-FAST 追平扩散 π0（含最难的叠衣服），所需 GPU 小时数少 5 倍 |

**5）推理延迟（第 VI-E 节）**

| 模型 | RTX 4090 上生成 1 秒动作块 | 原因 |
|---|---|---|
| π0（扩散 / 流匹配） | 约 100 ms | 10 步去噪，用 300M 动作专家 |
| π0-FAST | 约 750 ms | 自回归解码 30~60 个 token，用完整 2B 语言骨干 |

原文称在所评测的静态操作任务上更慢的推理没有损害性能，但让评测明显变慢。

### 消融实验说明了什么

| 消融 | 结果 | 说明 |
|---|---|---|
| 换骨干：OpenVLA 改多图输入 + 1 秒块，binning → FAST+（叠 T 恤） | 性能显著提升 | FAST 与骨干无关，可用于任何预训练自回归 Transformer |
| 去掉 BPE（收拾桌子、叠 T 恤） | 比朴素好，但比完整 FAST 差 | DCT 已集中信息，但大量重复的 0 稀释学习信号、拖慢推理 |
| 展平顺序 | 选低频优先（列优先） | 先定整体形状，rollout 更稳定（原文定性结论） |
| 压缩-保真权衡（附录 B） | FAST 在宽范围内表现好；低保真时不如 VQ 类高效，高保真时扩展性好得多 | 适合精细控制 |

## 优点与不足

| 优点 | 不足 / 疑问 |
|---|---|
| 不改骨干结构，任何自回归 Transformer 直接可用，复用 LLM 工具链 | 推理慢：约 750 ms/块 vs 扩散 π0 约 100 ms，高动态任务不适用 |
| 只有两个不敏感的超参数，无需训练额外编码器（对比 VQ / FSQ） | 压缩有损，保真度由缩放系数决定 |
| 训练 GPU 小时数少 5 倍，语言跟随更好 | 只在静态机械臂上验证了策略效果；移动机器人、灵巧手、人形只做了离线压缩测试 |
| FAST+ 通用 tokenizer 开源，三行代码可用 | 扩散与自回归哪种 VLA 架构更好仍无定论（原文自己也这么说） |
| 首个在 DROID 上零样本泛化到新环境的策略 | DROID 定量评测仅 44 次试验，三校园测试只有定性视频 |

原文给出的未来方向：在更多形态的机器人上测试策略性能；探索其他压缩方案，以及把压缩式动作编码与扩散等非自回归解码结合；借用 LLM 的推理加速技术（投机解码、量化、定制算子）。

## 我的问题与想法

- "每条臂每秒约 30 个 token"是否意味着动作信息量有某种固有上限？如果是，更高频的数据只是浪费采样，这对数据采集频率的选择有指导意义。
- 自回归版语言跟随更好、扩散版常忽略指令，这是解码方式的差异，还是动作专家把梯度"抢走"了？后续的知识隔离论文（π0.5-KI）专门研究了这个问题。
- 本文的 750 ms 延迟在接触任务上是否致命？ForceVLA 的实验里 π0-fast 基线明显弱于 π0-base，可能与此有关，但两篇论文都没有分析。
