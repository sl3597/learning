# 批判与开放问题：ForceVLA 的边界与下一步

> 本章把论文的优缺点摊开，列出它没回答的问题，并给出几组可以动手做的扩展实验。文末的 ❓ 清单是 Agent 系统的追踪对象。

## 学习目标

- 能用"证据 + 疑点"的方式评价一篇机器人学习论文。
- 能说出 ForceVLA 的 3 个结构性优点和 3 个主要局限。
- 能区分 ForceVLA 与后续工作 ForceVLA2，避免混用数字。
- 能从开放问题中挑一个，设计可执行的小实验。

## 前置知识

- 需要先读：[05 实验与结果](05-experiments-and-results.md)

## 核心概念

| 术语 | 一句话解释 | 类比 |
|---|---|---|
| **路由塌缩**（router collapse） | MoE 路由器把几乎所有输入都发给同一个专家 | 分诊台把所有病人都送到一个科室 |
| **负载均衡损失** | 惩罚专家使用不均的额外损失项 | 规定每个科室都要接诊一定比例 |
| **sim-to-real** | 仿真里训练、真机上用 | 模拟器练车后上路 |
| **跨具身**（cross-embodiment） | 同一模型在不同机器人上工作 | 同一个驾驶技能开不同的车 |

## 详细讲解

### 7.1 优点（有证据支撑的）

1. **模块化、可插拔**：FVLMoE 加在 VLM 之后、以相加方式注入动作专家，π0 本体不动；消融显示这是最优位置（80% vs 其它 ≤60%）。
2. **力是一等模态的思路被验证**：视觉遮挡场景 90% 成功，远高于所有基线（最高 60%），直接证明力补上了视觉的盲区。
3. **行为层面的改变**：U 盘插入失败后会重新调整/重抓，这是基线没有的"闭环纠错"。
4. **开源**：代码（Apache-2.0）与数据（HuggingFace）公开，复现门槛相对低。

### 7.2 局限（论文自认 + 我们发现的）

| 类别 | 问题 | 证据 |
|---|---|---|
| 作者自认 | 用的是估计外力，精度不如高保真 F/T 传感器 | 论文局限段落 |
| 作者自认 | 验证平台自带高成本力感知，低成本平台未验证 | 论文局限段落 |
| 数据一致性 | 消融基线 45% / ForceVLA 80% 与主表 37.3% / 60.5% 不一致，任务集未说明 | 表 3 vs §5.1 |
| 统计强度 | 每任务 10~20 次试验，无多种子方差 | §5.1 |
| 弱场景 | 不稳定插座 20%，低于 π0-fast w/ F 的 30%，未讨论 | 表 2 |
| MoE 设计 | top-1、无负载均衡，专家 0 占近一半 token，可能部分塌缩 | 附录 C |
| 力表示 | 只用当前时刻 1 个力 token，没有时间窗口，可能丢失接触瞬态 | §4 |
| 泛化范围 | 单一机械臂、单一实验室环境、5 个任务 | §3 |

### 7.3 与后续工作的关系

- **ForceVLA2**（同团队后续论文）：引入跨尺度 MoE（Cross-Scale MoE），报告在 5 个任务上相对 π0 提升 48.0 个百分点、相对 π0.5 提升 35.0 个百分点。

> ⚠️ 注意：这些是 **ForceVLA2** 的数字，不要写进 ForceVLA 的笔记或引用里。ForceVLA 本文的数字是 +23.2 个百分点（单任务平均 60.5%）。

> ❓ 待解决：ForceVLA2 的 arXiv 编号、"跨尺度"具体指什么（时间尺度还是特征尺度），需要另开一篇论文笔记。

### 7.4 值得做的扩展实验

| 实验 | 要回答的问题 | 最小做法 |
|---|---|---|
| 力的时间窗口 | 用最近 N 步力代替单步是否更好？ | 把 φ_F 改成 1D 卷积或小 Transformer，N = 5/10/20，比较单任务成功率 |
| 负载均衡 | 加均衡损失能否让专家真正分工？ | 加 Switch Transformer 式辅助损失，重做附录 C 的路由统计 |
| 专家数量 | 4 个是最优吗？ | 扫 2 / 4 / 8，看成功率与路由熵 |
| 外置 F/T 传感器 | 直接测量比估计好多少？ | 在同一臂上加腕部 F/T，训练两版对比 |
| 跨具身 | 换到另一台机械臂后还能用吗？ | 按 [06 章](06-reproduction-guide.md) 迁移，先做插插头单任务 |
| 触觉替代 | 把 6 维力换成 GelSight 触觉图像？ | 用小 CNN 编码触觉图为一个 token，复用 FVLMoE |

### 7.5 读论文的方法论小结

本专题示范的批判性阅读步骤：

1. **先找主张**：一句话总结里的数字（60.5%、+23.2）。
2. **核对出处**：同一个数字在正文、表格、项目页是否一致。
3. **看基线公平性**：基线是否"合理地"用了同样的信息（这里 w/ F 基线是公平的）。
4. **找弱场景**：表格里方法不占优的格子（不稳定插座）。
5. **列出未写的事**：损失函数、控制频率、H_action、负载均衡……
6. **转成实验**：每个疑问对应一个最小可做实验。

## 常见错误与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 把局限等同于"论文不好" | 混淆批判与否定 | 优点与局限并列，判断"在什么条件下可用" |
| 引用 ForceVLA2 的数字 | 两篇论文标题相近 | 引用前核对 arXiv 编号 |
| 扩展实验设计无对照 | 只改一个版本就下结论 | 至少保留原版作对照，并固定随机种子 |

## 小结

- 优点：模块化晚期融合、遮挡场景 90%、闭环纠错行为、开源。
- 局限：估计外力、样本少无方差、数字不一致、不稳定插座弱、MoE 可能塌缩、单臂单环境。
- ForceVLA2 是后续工作，数字不可混用。
- 六个扩展实验方向：时间窗口、负载均衡、专家数、外置 F/T、跨具身、触觉替代。

## 自测题

1. 论文作者自己承认的两个局限是什么？
<details><summary>答案</summary>（1）使用估计外力而非高保真直接测量；（2）验证平台依赖高成本内置力感知，低成本平台未验证。</details>

2. 为什么说"专家 0 占近一半 token"值得警惕？
<details><summary>答案</summary>这可能是路由塌缩的迹象：MoE 没有真正分工，多个专家的容量没被用上；论文也未使用负载均衡损失。</details>

3. 列出一个可以在自己机械臂上做的最小复现实验。
<details><summary>答案</summary>插插头单任务：在自己的机械臂上采 50 条带力演示，用 forcevla_lora 微调，20 次真机试验对比 w/o F 与 ForceVLA。</details>
